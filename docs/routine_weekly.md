# 주간 점검 루틴 — 지시문 (2026-09-08, 제안 7번)

> 클라우드 루틴 "주간 점검"의 프롬프트는 이 파일을 읽고 그대로 따르라는 몇 줄뿐입니다.
> 매주 월요일 08:30 KST에 돕니다. 사용자는 코드를 읽지 않습니다 — 이 루틴의 산출물은
> **쉬운 말로 된 한 장**과 휴대폰 알림 한 번입니다. 글을 고치거나 발행하지 않습니다.

## 절차

1. `pip install -r requirements.txt`
2. `python -m scripts.weekly_review` — 지난주(월~일) 보고서를 `reports/weekly_<일요일>.md`에
   쓰고 요약 몇 줄을 찍습니다. `python`이 없으면 `python3`.
3. 보고서를 `Read`로 읽고, **원고를 두 편만 직접 열어** 봅니다 — 절 수·시각자료가 가장 많은
   글과 가장 적은 글. 숫자만으로 안 보이는 것(소제목이 사람 말투인지, Fermata's Take가
   판단인지 요약인지, 같은 틀이 반복되는지)을 보고서 끝 "루틴이 본 것" 절에 3~5줄로 적습니다.
   근거 없는 칭찬은 쓰지 않습니다. 고칠 점이 없으면 없다고 씁니다.
4. `git add reports/ && git commit -m "주간 점검: <일요일 날짜>" && git push origin HEAD:main`
   (push 거부 시 `git pull --rebase origin main` 뒤 다시).
5. 휴대폰 알림 한 번(PushNotification): 요약 3줄 + "보고서: reports/weekly_<날짜>.md" +
   "이번 주 최고·최악 글 하나씩 짚어 주세요."

## 하지 않는 것

- 원고·설정·규칙을 고치지 않습니다. 규칙은 사용자의 답을 받은 뒤 사람(Claude 세션)이 고칩니다.
- 검색 노출·클릭 수치는 여기서 못 읽습니다(관리자 로그인 필요). 보고서에 "Claude 세션이
  덧붙인다"고만 적혀 있습니다.
- 알림은 한 번. 실패했으면 실패했다고 한 번.
