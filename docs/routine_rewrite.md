# 옛 글 재작성 루틴 — 지시문 (2026-09-08, 한시)

> 클라우드 루틴 "옛 글 재작성"의 프롬프트는 이 파일을 읽고 그대로 따르라는 몇 줄뿐입니다.
> 사용자 지시: "영어판을 제외하고 모든 글에 재테크농부 규칙으로 수정해라 … 옛 글까지 다시
> 써줘." 제목·소제목은 이미 고쳐 올렸고(2026-09-08 저녁), 이 루틴은 **본문 구조와
> 시각자료**를 새 규칙에 맞게 다시 씁니다. 목록이 비면 이 루틴은 할 일이 없습니다 —
> "남은 것 없음"이라고 보고하고 끝냅니다.

## 임무

한 번 실행에 **두 편까지** 다시 씁니다(한 편 30분 안팎). 40분이 지났으면 새 편을
시작하지 않습니다. 매 편은 **따로 커밋·푸시**합니다 — 커밋되면 `editorial_publish.yml`이
같은 글을 제자리에서 다시 올립니다(주소·글 번호 그대로).

## 대상 고르기

1. `git pull --rebase origin main`을 먼저 합니다(다른 실행이 방금 끝냈을 수 있습니다).
2. **`editorial/queue/*.json`**이 있으면 그중 파일명 순으로 첫 것. 이것은 시황 이전 옛 글
   (2026-08-28~31)을 원고 형식으로 옮겨 둔 것입니다. 다 쓴 뒤 `editorial/<market>_<date>.json`
   으로 **옮기고**(git mv) 큐에서 없앱니다. `wp_post_ids`가 들어 있어 기존 글 번호에 덮어씁니다.
3. 큐가 비었으면 `editorial/kr_*.json`·`editorial/us_*.json` 중 `"rewritten"` 키가 없는
   파일을 날짜 순으로. 다 쓰면 최상위에 `"rewritten": "<오늘 KST 날짜>"`를 넣습니다.
4. 둘 다 없으면 "남은 것 없음"을 보고하고 종료합니다.

## 먼저 읽을 것

- `docs/editorial-style.md` 전부 — 특히 「제목 문법」·「소제목」(사람이 쓴 것처럼)·「낱말」.
- `docs/routine_common.md`의 맨 위 블록과 6번(원고 작성)·「본문 데이터 그래픽」·「본문 사진」.
- `src/publish_editorial.py` 상단 주석(원고 형식).

## 다시 쓰는 방법

- **사실은 그대로, 구조만 새로.** 숫자는 원고의 `price_data`와 원래 본문에 있는 것만 씁니다.
  새 숫자를 지어내지 않습니다. `sources`는 그대로 두되 새로 확인한 기사가 있으면 더합니다.
  (관문의 숫자 대조 `editorial_facts`가 `price_data`와 맞춰 봅니다.)
- **10~14절**로 쪼갭니다. 한 절에 하나만 — 그날의 성격, 지수, 업종, 주인공 종목과 재료,
  다른 특징주, 수급, 환율·유가·금리, 다음 거래일. 절마다 1~3문단. 원래 본문의 문단을
  잘라 옮기고, 잇는 문장만 새로 씁니다. 첫 절은 숫자 나열이 아니라 그날 이야기로 엽니다.
- **소제목은 사람이 말하듯**: 절반은 완전한 문장(`~습니다`), 나머지는 짧은 이름표나 질문.
  32자 이하. 회사 이름으로 끝나는 헤드라인 꼴·`…한 것`·`…고, …고`는 관문이 막습니다.
- **제목은 이미 고쳐져 있습니다.** 그대로 둡니다(바꾸고 싶으면 「제목 문법」대로, 최근 다섯 편과
  뼈대가 다르게).
- **시각자료 6개 이상**(표지 제외), 그날 이야기에 맞게:
  - `price_history` 지수(`KS11`/`^GSPC` 등, `guide`로 7,000선 같은 고비) + 주인공 종목
    (`price_data`에 `history`가 있는 종목만 — 편입 종목도 있으면 됩니다).
  - `number_cards` (지수·환율·유가 등 2~4개, `note` 한 줄).
  - `sector_bars`, `movers_list`, `flow_compare`(외국인·기관이 반대로 간 종목이 있을 때),
    `stock_spotlight`, `two_day_compare`(전날 시세 파일이 있을 때).
  - `investor_flows`는 원래 본문에 투자자별 순매수 금액과 출처가 있을 때만(`source` 필수).
  - 주인공이 코어 종목이면 그 절에 `"photo": {"ticker": "<코드>"}`.
  - 그림만 붙이고 본문이 설명하지 않으면 장식입니다 — 그 절 본문이 그 그림을 말해야 합니다.
- `insight_section`·`outlook`·`closing`은 있으면 그대로 두되, 소제목·낱말 규칙에 걸리는 것은
  고칩니다. `closing.heading`은 `Fermata's Take`.
- **영어판(`en`)은 손대지 않습니다.** 사용자가 영어판을 뺐습니다. 있으면 그대로 둡니다.
- 큐 원고(옛 글 5편)는 `ko.narrative`가 옛 HTML에서 옮겨 온 것이라 문체가 다를 수 있습니다.
  `docs/editorial-style.md` 문체(존댓말, 한 문장짜리 문단, `하락했습니다`)로 다듬습니다.

## 관문

`python -m src.editorial_gate <원고>` — "관문 통과"가 나올 때까지 고칩니다. 관문이
`output/gate/`에 그린 그림은 `Read`로 봅니다(축이 한 종목에 잡아먹히거나 이름이 어긋나면
고칩니다). 통과 전에는 커밋하지 않습니다.

## 커밋

큐 원고: `git mv editorial/queue/<파일> editorial/<파일> && git add editorial/<파일> && git commit -m "옛 글 재작성: <거래일> <시장>" && git push origin HEAD:main`
기존 원고: `git add editorial/<파일> && git commit -m "옛 글 재작성: <거래일> <시장>" && git push origin HEAD:main`
push가 거부되면 `git pull --rebase origin main` 뒤 다시. 3분 넘게 워크플로를 기다리지 않습니다.

## 절대 규칙

- `output/`·`data/`를 커밋하지 않습니다. 한 실행에 두 편까지.
- 숫자는 `price_data`와 원래 본문에서만. 마크다운 볼드(`**`) 금지, 강조는 `<b>…</b>`.
- 알림은 보내지 않습니다. 실패해서 한 편도 못 썼을 때만 휴대폰 알림 한 번.
